# MeetLens MVP 要件定義

## 概要
会議の品質を分析・可視化するWebアプリケーションのMVP。
VTTファイルをアップロードし、議事録自動生成と品質スコアリングを行う。

想定する利用形態: **情シスが運用する社内向けの内製アプリ**。テナントは部署・チーム単位とする。

参照: [meetlens-concept.md](../meetlens-concept.md)

---

## MVPスコープ

### Must（MVP必須）

#### 1. 認証・テナント管理
- Cognito によるログイン
- **招待制**（セルフサインアップは設けない）。招待されたユーザーは初回ログイン時にパスワードを設定する
- テナント分離（データ設計・認証にTenantIDを組み込む）
  - 1ユーザーは1テナントにのみ所属する
  - テナント内の全員が、テナント内の全会議を閲覧できる（アップロード時にその旨を表示する）
  - TenantID はクライアントから受け取らず、ログイン中のユーザーの所属からサーバー側で決める
- 利用停止したユーザーは、ログイン済みでもAPIにアクセスできないようにする

##### ロール
| ロール | 想定する人 | できること |
|---|---|---|
| システム管理者 | 情シス（ユーザーサポート担当） | テナントの作成・編集・無効化、テナント管理者の任命・解除、全テナントのユーザー管理（招待・利用停止など）。**会議の内容は閲覧できない** |
| テナント管理者 | 部署・チームの代表 | 自テナントのユーザーの招待・一覧・利用停止。一般ユーザーの操作もすべて可能 |
| 一般ユーザー | 部署・チームのメンバー | 会議のアップロード、自テナントの会議一覧・詳細の閲覧 |

- テナントの最後の管理者は解除・利用停止できない（復旧はシステム管理者が行う）

#### 2. VTTアップロード
- .vttファイルのアップロード（Teams/Zoom/Webex対応）
- アップロード時のメタデータ入力:
  - 会議タイトル
  - 開催日時
- 会議タイプは画面では入力させず、データ上は「定例」として保持する（将来のタイプ追加に備える）

#### 3. 議事録自動生成
- VTTをパースし、LLM（Bedrock）で議事録を生成
- 日本語の音声認識誤りをLLMに文脈から補正させる

#### 4. 会議の質分析・スコア化
- 対応する会議タイプ: **定例** のみ

##### 定例の評価指標
| 指標 | 算出方法 |
|---|---|
| 意思決定数（明確な決定 / 保留・先送り / 未決） | LLM |
| アクションアイテムの具体性（担当者・期限の有無） | LLM |
| 脱線率 | LLM |
| 発言量の偏り | ルールベース（VTTの話者・時間から計算） |

#### 5. ダッシュボード・会議一覧
- テナント内の会議一覧表示
- 各会議のスコアサマリー・処理状態（処理中 / 完了）を一覧で確認

#### 6. 会議詳細表示
- 議事録の閲覧
- 分析結果・スコアの表示

### Out of Scope（MVP後に検討）
- ファクトチェック機能（Web検索API連携）
- HTML生成・ストック（フロントエンドで直接表示するため不要）
- 会議タイプ追加（1on1、デイリースクラム、ブレスト・ふりかえり）と、タイプごとの評価の重み付け
  - 1on1 は「部下の発言比率」のために上司・部下の判別が必要
- 時間あたりの議題消化率（議題の特定にアジェンダ事前登録が必要）
- トレンド分析（会議シリーズの品質推移）
- 会議シリーズの概念
- アジェンダ事前登録と消化率
- 通知・アラート
- VTT自動取得（Microsoft Graph API連携）
- 社内SSO連携（Entra ID 等。Cognito の SAML/OIDC 連携で後から追加する）
- 複数テナントへの所属・テナントの切り替え、会議ごとの共有範囲の設定

## 非機能要件

| 項目 | 方針 |
|---|---|
| 利用規模 | 数人・月数十件程度（同時アクセスはほぼ考慮しない） |
| AWS利用料 | 月1000円以下を目安とする |
| 分析処理 | 非同期（アップロード後は「処理中」を表示し、完了後に結果を表示） |
| VTT上限 | 1ファイル1MB程度・会議2時間程度まで |
| データ保持 | VTT原本・議事録・分析結果ともに無期限保持 |

技術スタック・LLMのモデル選定は [tech-stack.md](../tech-stack.md) を参照。

## 実装の進め方

いちばん不確実な「LLMのスコアに意味があるか」を先に確かめ、次に全レイヤーを細く通してから肉付けする。

| 段階 | 内容 | 目的 |
|---|---|---|
| 1. スパイク | ローカルの Python スクリプトで、実際のVTT → Bedrock → 議事録・スコアを試す（AWSの構成は作らない） | LLMの結果の質を早く確かめる |
| 2. ウォーキングスケルトン | アップロード → S3 → Lambda → Bedrock → DynamoDB → 一覧・詳細表示を AWS 上で細く1本通す。TenantID は固定値で入れる | サーバーレス構成の結合を早く確かめる |
| 3. 認証の組み込み | Cognito でログインし、TenantID をトークンから取るように替える | 認証・テナント分離を載せる |
| 4. ユーザー・テナント管理 | 招待・利用停止、テナント管理者・システム管理者の画面 | MVP完成 |

- テナント分離は後から入れにくいため、段階2から TenantID による絞り込みを前提に作る
- 認証・ユーザー管理は学習目的のため MVP の完成条件に含める
